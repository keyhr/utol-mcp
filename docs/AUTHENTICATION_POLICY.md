# UTOL MCP 認証方針

> このドキュメントは、当初の認証方針（`utol-mcp-authentication-policy.md`）を基に、
> データアクセスの範囲を一点改訂した版です。改訂点は「データアクセスの範囲」節に明記しています。

## 目的

このプロジェクトは、UTOLを学生本人がより便利に使うための、ローカル実行を前提とした個人用MCPサーバーです。

対象は、本人が通常のUTOL利用で閲覧できる情報に限ります。たとえば、受講登録済みの科目、締切、お知らせ、教材リンクなどを整理することを目的とします。

## 基本方針

このプロジェクトは、UTokyo SSO、多要素認証、アクセス制御、CAPTCHA、レート制限を回避しません。

認証は常にユーザー本人の操作によって行います。ツールは、ユーザーのパスワード、多要素認証コード、認証アプリの情報、秘密鍵などを収集・保存・送信・処理しません。

## 想定する運用類型

法的・規約上の評価は運用形態によって変わるため、本プロジェクトは次の類型を区別します。

- **(1) 本人によるローカル利用（既定・推奨）**: stdio モードで、本人の端末上でツールを実行する。セッション・キャッシュ・監査ログはすべて本人端末に置く。
- **(2) 本人が管理する専有ホストでのリモート利用**: HTTP モードを、本人のみが管理・利用する専有ホスト上で稼働させる。第三者はアクセスしない。
- **(3) 第三者向けサービス提供**: 本人以外の利用者にアクセスさせる運用。**本プロジェクトはこれを想定・支援しません（非対応）。**

類型 (2) を採用する場合の要件は「セッションの扱い」節に記載します。類型 (3) は、UTokyo Account の共有禁止（大学規則）や不正アクセス禁止法上の論点、個人情報保護法上の事業者義務、AGPL 第 13 条への対応など、単一利用者利用にはない多数の課題を伴うため、実装・運用の対象外とします。

## 前提として利用者が確認すべき事項

本プロジェクトは技術的に UTokyo SSO・MFA を回避しませんが、**UTOL および東京大学の情報システム利用規程が、自動アクセス（スクレイピング）・認証セッションのローカル保存と再利用・教材の外部サービス（クラウド LLM を含む）への送信・受講登録/解除の自動化を許容するかは、利用者が原文で確認する責任を負います。** これらが規程で禁止されている場合、本ツールの利用は、技術的な適法性とは別に、学内処分や契約上の責任の対象となり得ます。

## ログイン方式

ツールは、次のようなローカルCLIコマンドを提供できます。

```bash
utol-mcp login
```

このコマンドは、通常のブラウザ画面を開き、ユーザーが公式のUTokyo Accountログインページで手動ログインするためのものです。

ログイン処理そのものは、大学が提供する正規のSSO画面上で行われます。ツールは、ユーザー名・パスワード・多要素認証情報を代理入力しません。

## セッションの扱い

ログイン後、ツールはローカルに保存されたブラウザセッションを再利用できます。

このセッションは、ユーザー本人が管理する環境にのみ保存します。ブラウザプロファイル、Cookie、localStorage、その他のセッション情報は認証情報に準じる機密データとして扱います。

セッション情報は、Gitリポジトリ、ログ、バグレポート、クラウドストレージ、第三者サービスに含めてはいけません。

### 類型 (2)（本人管理の専有ホストでのリモート利用）における要件

HTTP モードを本人の専有ホスト上で稼働させる場合、セッション・キャッシュ・教材データはそのホストのディスク上に置かれ、MCP 応答として遠隔クライアントへ送られます。この形態は「本人の端末上にのみ保存」という原則の拡張であり、本人が排他的に管理するホストに限って許容します。この場合、次を満たしてください。

- MCP クライアントとの通信を TLS（HTTPS）で暗号化する。
- ディスク上のセッション・秘密情報を保護する（ディスク暗号化・アクセス権限・バックアップからの除外）。
- ホスト上の OS アカウントを分離し、他者がセッションを読めないようにする。
- パスフレーズ・OAuth トークン・セッションの失効手順（`logout`・トークン失効・パスフレーズ変更）を用意する。
- 第三者にホストのアクセス経路・パスフレーズ・トークンを渡さない（渡した時点で類型 (3) となり非対応）。

これらを満たせない場合は、類型 (1)（本人端末でのローカル利用）を用いてください。

ツールは、ローカルのセッション情報を削除するためのコマンドを提供するべきです。

```bash
utol-mcp logout
```

## MCPサーバーの責務

MCPサーバーは、原則として読み取り中心の機能のみを提供します。

想定されるツール例は以下です。

```txt
auth_status
open_login
refresh_cache
list_courses
list_deadlines
list_announcements
search_materials
```

未ログインまたはセッション期限切れの場合、MCPサーバーはパスワード等を用いた自動ログインを試みず、ユーザーに手動ログインを促します。

### サイレント SSO 再認証についての明確化

UTOL のアプリケーションセッション（`SESSION` Cookie）はセッション Cookie であり、ブラウザプロセス終了時に失われます。一方、ユーザーが手動ログイン時に確立した SSO（IdP）側のセッションは、永続 Cookie として端末に残ることがあります。

このとき、UTOL の SSO エントリ（`/saml/login?disco=true`）へアクセスするだけで、**資格情報の入力も多要素認証も一切なく、リダイレクトのみで**アプリセッションが再確立される場合があります。本ツールはこれを「サイレント SSO 再認証」と呼び、次の条件で許容します。

- 許容する条件: ユーザーが過去に手動で確立した IdP セッションが有効で、**一切の対話（資格情報入力・MFA・アカウント選択）を要さずに**再認証が完了する場合のみ。
- 禁止する挙動: 資格情報・MFA コードの代理入力、SSO/MFA の回避。再認証の途中で資格情報・MFA・アカウント選択が要求された時点で、ツールは**直ちに処理を中止**し、ユーザーに `utol-mcp login` による手動ログインを促します。

これは「パスワードを使った自動ログイン」ではなく、ユーザー自身が確立済みの正規 SSO セッションを対話なしで再利用するものであり、SSO・MFA を回避しません。

## OAuth/OIDCについて

このプロジェクトは、UTokyo SSOのOAuth/OIDCクライアントとして振る舞いません。

大学から正式にOAuth/OIDCクライアントとして登録されていない限り、認可コード、アクセストークン、IDトークンなどを直接取得しようとしてはいけません。

未公開の認証エンドポイント、内部API、リダイレクトURI、既存クライアントIDの流用、モバイルアプリ用トークンの流用などを使って、正規のクライアント登録を迂回してはいけません。

## データアクセスの範囲

ツールがアクセスしてよいのは、認証済みユーザー本人が通常のUTOL画面で閲覧できる情報に限ります。

### 改訂（受講登録外コースの公開カタログ情報の扱い）

当初方針では、アクセス不可の対象として「自分が受講登録していない科目の情報」を一律に挙げていました。しかし、UTOL には任意の学生が開講科目を探すための**公式のコース検索機能**が存在し、そこでは受講登録外コースの公開カタログ情報（コース名・担当教員・開講期・開講組織・コース概要説明・シラバスへのリンク）を通常の画面上で閲覧できます。

そこで本項を次のように改訂します。

- **取得してよい（受講登録外コースを含む）**: 公式コース検索画面およびシラバス画面が公開する**公開カタログ情報のみ**。具体的には、コース名、担当教員名、開講期・開講区分、開講組織、コース概要説明、シラバス、およびそれらへのリンク。
- **取得してはいけない（受講登録外コース）**: 受講登録・参加を前提とする**アクセス制御された内部コンテンツ**。具体的には、受講登録外コースの教材ファイル、課題、小テスト、お知らせ本文、掲示板、成績、メッセージなど。これらは通常の画面では閲覧できず、アクセス制御で保護された領域に該当します。

この改訂は、「認証済みユーザー本人が通常のUTOL画面で閲覧できる情報に限る」という基本原則の範囲内での明確化です。受講登録外コースの保護された内部情報を取得しないという禁止は維持されます。

### 引き続きアクセスしてはいけないもの

- 他ユーザーの非公開情報
- 管理者・教員・TA向けの権限が必要な情報
- 受講登録外コースの、アクセス制御された内部コンテンツ（教材・課題・お知らせ本文・成績・メッセージ等）
- 非公開API
- 隠しページ
- アクセス制御で保護された領域

## レート制限とキャッシュ

このプロジェクトは、大量アクセスや一括収集を目的としません。

更新処理は、ユーザー操作による実行、または十分に低頻度な実行に限定します。並列クロール、短時間の連続リクエスト、全科目・全教材の無制限取得は避けます。

取得済みデータはローカルキャッシュを優先して利用し、UTOL本体へのアクセス回数を抑えます。

## 書き込み操作

初期状態では、MCPサーバーはUTOLに対する書き込み操作を提供しませんでした。

現在は、利用者本人の明示的な要望に基づき、一部の書き込み操作を**ガードレール付き**で提供します。すべての書き込み操作は、各操作ごとに次を満たします。

- **送信前プレビュー**: `confirm:true` が指定されない限り、実行せず変更内容のプレビューのみを返す。
- **明示的な確認**: 実行には `confirm:true` の明示指定を必須とする。
- **監査ログ**: 実行・失敗を `~/.utol-mcp/audit.log` に記録する。
- **可逆性の説明**: 各操作の可逆性・影響をレスポンスに明示する。

提供する書き込み操作:

- 課題の「提出不要」フラグ変更（`set_task_no_submission`、可逆）
- 受講登録（`register_course`、解除可能）
- 受講登録解除（`unregister_course`、受講登録・提出物に影響する可能性があるため要注意）

引き続き**実装しない**書き込み操作:

- 課題提出・小テスト回答
- 掲示板投稿・メッセージ送信
- ファイルアップロード

これらを将来扱う場合も、上記のガードレール（プレビュー・明示確認・監査ログ・取消不能性の説明）を必須とします。

## 保存データ

保存するデータは、個人利用に必要な最小限にします。

保存対象は、締切、科目名、お知らせタイトル、教材リンク、更新日時などを中心とします。講義資料、提出物、成績、メッセージ本文などの保存は、必要性と規約上の問題を慎重に確認したうえで扱います。

保存データは、ユーザー本人が管理する環境（類型 (1) の本人端末、または類型 (2) の専有ホスト）に置きます。本プロジェクト自身は、保存データを開発者や無関係な第三者のサーバーへ送信しません。

### 教材内容と MCP クライアント（LLM）への送信

ただし、`get_material` は教材内容を MCP クライアントのコンテキストへ取り込むため、そのクライアントがクラウド LLM である場合、教材内容は当該 LLM 事業者へ送信されます。また、`list_announcements` などが返す情報には、他の学生・教員の氏名や連絡先、授業内限定情報が含まれ得ます。

この送信について、次の点に留意してください。

- 著作権法 30 条（私的使用のための複製）・30 条の 4（非享受利用）による正当化は不確実であり、教材を要約・質問回答に用いる利用は「表現の享受」を含むのが通常です。
- 教材や授業に複製・外部送信を制限する個別指示がある場合は、その指示が優先されます。
- 第三者（他の学生・教員）の個人情報・秘密情報を LLM 事業者へ送ることは、個人情報保護法が直接適用されない個人利用であっても、プライバシー侵害・秘密保持義務違反・不法行為を構成する余地があります。
- 対応として、送信の必要最小限化、送信先 LLM の学習利用・ログ保存の無効化設定の確認、機微な教材についてのローカルモデルまたは学内承認済みサービスの優先を推奨します。

## 禁止事項

このプロジェクトでは、以下を実装しません。

- SSO回避
- 多要素認証回避
- CAPTCHA回避
- bot検知回避
- stealthブラウザ機能
- パスワードを使った自動ログイン
- Cookieやセッショントークンの共有・エクスポート
- 他人のアカウントでの利用
- 講義資料の大量ダウンロード
- 講義資料や教材の再配布
- ユーザー権限外の情報取得

## OSSとしての公開方針

このプロジェクトを公開する場合、READMEには以下を明記します。

- このツールは個人の学習支援を目的とすること
- UTokyo SSOやMFAを回避しないこと
- 認証はユーザー本人が正規ログイン画面で行うこと
- ユーザーは大学の規則、UTOLの利用規程、関連法令を守る必要があること
- このツールは大量アクセスや教材収集を目的としないこと
- セッション情報は機密情報として扱う必要があること
- 受講登録外コースについては公開カタログ情報とシラバスのみを取得対象とし、保護された内部コンテンツは取得しないこと

利用者は、大学の情報システム利用規程、UTOLの利用規程、授業ごとの指示、著作権、個人情報保護に関するルールを遵守する責任があります。

このプロジェクトは、正規に閲覧できる情報を本人の端末上で整理するための補助ツールとしてのみ利用します。
